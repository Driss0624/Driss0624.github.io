# Feature Specification — Project Layout (Header & Footer)

*Feature 2 of 8 · Branch: `feature/module-16-header-footer` · Must be used with `ai/ai-spec.md` · Last updated: 2026-11-03*

---

## 1. Feature Goal and Outcomes

Give every page one shared frame, so the site reads as a single professional product on desktop and on a phone.

When this feature is done:

- Every route renders inside `MainLayout`, between one `Header` and one `Footer`.
- The header stays visible while scrolling, shows the AI-generated logo, and links to every public page with the current page highlighted.
- On viewports of 768px or narrower, navigation becomes an icon bar fixed to the bottom of the screen that never hides page content.
- The footer shows contact links and a copyright notice on every page.
- Colors, spacing, and typography come from shared CSS custom properties that later features reuse.

---

## 2. Feature Scope

### In scope

- `MainLayout`, `Header`, and `Footer` components, and wiring `MainLayout` around the route table.
- Navigation links to Home, Portfolio, Links, and Contact, with the active page indicated.
- The responsive navigation: horizontal links on desktop, a bottom icon bar on mobile.
- The AI-generated logo: file, `alt` text, link to Home, and documented generating tool.
- Footer contact information (email, GitHub, LinkedIn) and copyright notice.
- Global styles: design tokens (CSS custom properties), base typography, and the single 768px breakpoint.

### Out of scope

- Page content for Home, Portfolio, Links, Contact, Login, and Back Office (their own features). The placeholder headings stay.
- Any Supabase call. Layout components never import `supabaseClient.js` (`ai-spec.md` §7).
- Light/dark mode and language switching (extra miles, only after the main requirements).
- New dependencies. Icons use `react-icons`, already installed.
- Replacing the favicon is optional polish and is done only if the logo file makes it free (see Needs review).

---

## 3. Constraints

- Follow every constraint in `ai/ai-spec.md` §5, §7, and §11: custom CSS only, one component per file, the 768px breakpoint, `alt` text on every image, a documented tool for every AI image.
- `#/login` and `#/backoffice` never appear in the header, the footer, or the mobile navigation (`ai-spec.md` §11; business doc "Hidden Routes").
- Layout components contain no page content and no data fetching.
- The mobile bar must not obstruct content: the page reserves bottom space equal to the bar's height.
- Navigation is keyboard-reachable, has a visible focus style, and mobile icons carry accessible names (`aria-label`).
- External footer links open in a new tab with `rel="noopener noreferrer"`.
- No contact detail or URL is invented. The email and LinkedIn URL are supplied by Driss before implementation.

## 5. Requirements Breakdown and User Flow

| ID | Requirement |
| --- | --- |
| LAYOUT-FR-01 | A `MainLayout` component renders `Header`, then the current page inside `<main>`, then `Footer`. Every route in `ai-spec.md` §4 renders inside it. Pages render no header or footer of their own. |
| LAYOUT-FR-02 | `Header` renders in a `<header>` element at the top of every page and stays visible while the page scrolls. Its background and styling are identical on every page. |
| LAYOUT-FR-03 | The header navigation links to Home (`#/`), Portfolio, Links, and Contact, and to nothing else. Login and Back Office are never linked. |
| LAYOUT-FR-04 | The link for the current page is visibly distinct (color and indicator) and carries `aria-current="page"`. Home is active only on `#/`, not on every route. |
| LAYOUT-FR-05 | The header shows the AI-generated logo. Clicking it navigates to Home. It has descriptive `alt` text, and its generating tool is documented in this spec and in a code comment. |
| LAYOUT-FR-06 | The logo scales with the viewport and never overflows the header. |
| LAYOUT-FR-07 | On viewports wider than 768px, navigation links are text, displayed horizontally in the header. |
| LAYOUT-FR-08 | On viewports of 768px or narrower, navigation becomes an icon bar fixed to the bottom of the viewport. Each item shows a `react-icons` icon and a short label, and has an accessible name. The active item is highlighted. |
| LAYOUT-FR-09 | The mobile bar never covers page content: `<main>` and the footer reserve bottom space equal to the bar's height. |
| LAYOUT-FR-10 | `Footer` renders in a `<footer>` element at the bottom of every page, with contact information (email as a `mailto:` link, GitHub, LinkedIn) and a copyright notice with the current year and Driss Elhail's name. |
| LAYOUT-FR-11 | Global styles define design tokens as CSS custom properties (colors, spacing, font, radius, header and mobile-bar heights) and base rules: readable text, images that scale (`max-width: 100%`), and no horizontal scrolling at any width from 320px. |
| LAYOUT-FR-12 | Navigation is keyboard-reachable in a logical order, with a visible focus style on every link. |

### User flow (visitor)

1. Opens any page: sees the logo and navigation at the top, the page content, and the footer at the bottom.
2. Scrolls: the header stays at the top (desktop) and the icon bar stays at the bottom (mobile).
3. Clicks a navigation item or the logo: the page changes, the path stays `/`, and the active item updates.
4. Opens `#/login` by typing it: the page shows inside the same layout, and nothing in the navigation points to it.

### Design tokens (dark, modern)

| Token | Purpose | Starting value |
| --- | --- | --- |
| `--color-bg` | Page background | pale slate (`#c8c6d7`) |
| `--color-surface` | Header, footer, mobile bar | thistle cards (`#bfacc8`); indigo (`#4f1271`) in header, footer, mobile bar |
| `--color-text` | Body text | indigo (`#4f1271`); white in header, footer, mobile bar |
| `--color-muted` | Secondary text | vintage grape (`#4a4063`); pale slate in header, footer, mobile bar |
| `--color-accent` | Links, active state, focus | indigo (`#4f1271`); white in header, footer, mobile bar |
| `--font-sans` | All text | `Inter`, then system sans-serif |
| `--header-height`, `--mobilenav-height` | Layout offsets | about 64px each |

Values may be tuned to match the logo, but each must keep at least 4.5:1 text contrast against its background.

### Behavior by viewport

| Width | Header | Navigation | Footer |
| --- | --- | --- | --- |
| > 768px | Sticky; logo left, text links right | Horizontal text links | Normal flow |
| ≤ 768px | Sticky; logo only | Fixed bottom icon bar | Padded so the bar never covers it |
